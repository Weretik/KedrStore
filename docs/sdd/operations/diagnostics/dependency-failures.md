# When a dependency fails

What breaks when one outside part stops answering, what keeps working, what the system does on its own, and what a person does. Targets for how fast each must be noticed are in [quality targets](../../architecture/overview/quality-targets.md); alerts are the Cloud Monitoring checks on `/health/ready` and the API errors.

| Dependency | What breaks | What keeps working | What the system does | What a person does |
| --- | --- | --- | --- | --- |
| PostgreSQL (managed, adm.tools) | Every API call that reads or writes: the admin, the manager app online, the site's fresh data; `/health/ready` answers 503 | The site's cached pages; the manager app keeps orders in its offline queue and sends them later with the same `Idempotency-Key` | Requests fail fast with 500/503; nothing is half-saved (one transaction per command); the uptime alert fires | Check the database in the adm.tools panel; if data is lost, restore by [backups and restore](../data/backups-and-restore.md) |
| `Host.Api` on Cloud Run | The same as above, the database is fine | Cached site pages; the manager app's offline queue | Cloud Run restarts a failing instance; the uptime alert fires | Open the service's revisions and logs ([deploy](../deployment/github-actions-deploy.md)); roll back to the previous revision if a deploy caused it |
| Cloudflare Worker `api.classkedr.com.ua` | Site data, admin and the manager app cannot reach the API, though Cloud Run is healthy | Cloud Run itself; Cloud Scheduler still ticks the API directly | Nothing; the uptime check on the public host fails | Check the Worker and its secret ([Cloudflare API proxy](../deployment/cloudflare-api-proxy.md)) |
| 1C (SOAP) | Orders do not reach 1C; the catalogue, prices, stock and customer imports fail | Orders are saved in Kedr and shown to the manager; the catalogue keeps the last imported data | Orders wait in the Sales outbox and are retried by «Досилання повідомлень» inside the sending window; after 10 failures the order is `DeadLetter` and managers get a Telegram message with an Excel file of its lines; a failed import is a red task on «Фонові задачі» | Fix 1C or its access, then «Повторити» on the order ([1C runbook](../jobs/sales-one-c-runbook.md)); rerun the import task |
| Telegram Bot API | Quick-order and «not reached 1C» messages to managers | Orders and quick orders are saved; 1C delivery is not affected | The outbox retries each message; the order is never sent twice to 1C because of it | Check the bot token and chat (`Telegram:*` secrets); the messages arrive after the fix |
| CDN (cdn.express, FTP + HTTPS) | Uploading new pictures in the admin; if HTTPS is down, pictures on the site and in the app | Everything else; the site shows text and prices | The upload answers with an error and saves nothing; the CDN sync task fails red | Check the CDN account and credentials ([media CDN runbook](../jobs/media-cdn-sync-runbook.md)); upload again |
| Site refresh (`kedr-site` `/api/revalidate`) | «Оновити сайт зараз» answers 502; the site shows old data until its cache expires (minutes to hours) | Saving in the admin; the API | The button shows the error; nothing else depends on it | Press it again later, or wait for the cache time |
| Cloud Scheduler `kedr-tick` | Background tasks and the outbox stop: no imports, no retries to 1C or Telegram | Every request; the first try of a quick order's Telegram message right after the request (orders to 1C wait for the tick) | Nothing; «Фонові задачі» shows no new runs | Resume or fix the job ([background tasks](../jobs/background-tasks.md)); the next tick catches up |
| Cloud Run Job `kedr-tasks` | Imports and other tasks do not run | The API and the outbox (sent by the API itself) | The tick marks a run that never started or never finished as failed on «Фонові задачі» | Open the job's executions and logs; run the task again from «Фонові задачі» |
| Secret Manager | A new revision or job execution cannot start | The running revision keeps its secrets | The deploy fails | Check the secret and the service account's access, then deploy again |
| Cloud Logging / Cloud Trace | Logs or traces are missing | Everything for the users | Nothing | Nothing urgent; check the project's quotas |
| YouTube oEmbed | The admin cannot fill a video's title and picture from a link | Saving content by hand; the site | The call stops after 5 s with a message | Fill the fields by hand or try later |
