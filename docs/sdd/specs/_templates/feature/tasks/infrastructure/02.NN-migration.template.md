# Template of subphase 02.NN — Infrastructure: migration

- [ ] TNN1 Create a migration with the CLI command, not manually: `dotnet ef migrations add <Name> --project <Infrastructure.csproj> --startup-project <Api.csproj> --context <DbContext>`; do not edit applied migrations.
- [ ] TNN2 View generated operations/SQL: data loss, locks, default values, backfill and order of changes. Manual change of the new migration is permissible only for the agreed case, which the generator cannot express correctly.
- [ ] TNN3 Apply migration with the CLI command to an empty test database: `dotnet ef database update --project <Infrastructure.csproj> --startup-project <Api.csproj> --context <DbContext>`; check schema, indexes and constraints.
- [ ] TNN4 If the command is available in the installed version of EF Core, execute `dotnet ef migrations has-pending-model-changes --project <Infrastructure.csproj> --startup-project <Api.csproj> --context <DbContext>`.
- [ ] TNN5 For a risky change, generate and test deployment SQL via `dotnet ef migrations script --idempotent --project <Infrastructure.csproj> --startup-project <Api.csproj> --context <DbContext> -o <migration.sql>`; commit rollout/rollback or expand-contract plan to `<link to design/operations>`.

## Checkpoint

Migration is generated and verified by CLI commands; the risks of production rollout and data recovery are known.
