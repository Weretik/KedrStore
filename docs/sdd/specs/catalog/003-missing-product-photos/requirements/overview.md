# Відсутні фотографії товарів — огляд і межі

## Мета

Як адміністративний клієнт, я хочу отримувати сторінковий список активних товарів,
фотографії яких недоступні, щоб можна було виправити відсутні чи зламані медіафайли
каталогу без окремого запиту до CDN для кожного товару з браузера.

## У межах роботи

- Одноразова операція перевірки фотографій, яка досліджує кожен активний товар
  Catalog, зокрема товари, для яких `ExportToSite` дорівнює `false`.
- Збережений стан доступності для поточного URL фотографії товару.
- Сторінковий endpoint читання з анонімним доступом, який містить наявний
  адміністративний рядок товару й останній результат перевірки фотографії.
- Вважати відсутній файл, відповідь не із зображенням і невдалу перевірку
  недоступними для споживача API, зберігаючи їхні різні діагностичні статуси.
- Скидати стан перевірки до невідомого після зміни збереженого URL фотографії.
- Виключати товари з м'яким видаленням і видаляти залежний рядок перевірки
  після фізичного видалення товару.
- Команда `Host.Jobs` і створення або оновлення Cloud Run Job з наявного
  образу задач під час розгортання.
- Структурована діагностика, міграція, документація контракту, тести й
  оновлення операційного runbook.

## Поза межами роботи

- Завантаження, зміна чи видалення файлів CDN.
- Приховування товарів у публічному каталозі за доступністю фотографії.
- Реалізація frontend або перевірка URL у браузері.
- Автентифікація чи авторизація нового endpoint; для цієї функціональності
  він навмисно анонімний.
- Фільтрація товарів за `ExportToSite`.
- Внутрішній scheduler або ресурс Cloud Scheduler. Оператор володіє
  розкладом виконання.
- Автоматичний запуск задачі перевірки фотографій під час розгортання.
- Ручний HTTP endpoint, який запускає перевірку або повторно перевіряє один товар.

## Учасники й зовнішні системи

- Адміністративний клієнт: читає останній збережений список недоступних фотографій.
- Імпорт Catalog: створює невідомий стан для нового товару й інвалідовує
  застарілий стан після зміни URL фотографії.
- Host.Jobs: виконує один повний цикл перевірки й завершується.
- CDN: відповідає на HTTP-перевірки URL зображень товарів.
- PostgreSQL: зберігає товар і стан останньої перевірки.
- GitHub Actions і Google Cloud Run Jobs: створюють або оновлюють виконувану
  задачу, але не планують і не запускають її.

## Відкриті питання

Немає. Розклад, анонімний доступ, охоплення всіх активних товарів, HTTP fallback
і семантику недоступності, видиму споживачу, погоджено.
