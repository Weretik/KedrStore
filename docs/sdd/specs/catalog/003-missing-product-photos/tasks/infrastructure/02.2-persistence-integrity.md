- **Покриває:** SC-007

- **Рівень тесту:** інтеграційний PostgreSQL

## Свідчення

- Цільовий тест: `ProductPhotoCheckPersistenceTests` і перевірка метаданих моделі EF.
- Команда Red й очікуваний поведінковий збій: `dotnet test tests/IntegrationTests/IntegrationTests.csproj --no-restore --filter FullyQualifiedName~ProductPhotoCheckPersistenceTests` — assertion коректної моделі не пройшов: очікувалися два обмеження стану, фактично їх було нуль.
- Команда Green і результат: та сама цільова команда — перевірка метаданих пройшла; три перевірки життєвого циклу PostgreSQL локально пропущено через недоступність Docker.
- Нотатки Refactor: зв'язок, перетворення enum, токен конкурентності, обмеження, індекс і каскад залишаються в конфігурації Infrastructure; domain-переходи не залежать від провайдера.
- Команда Regression і результат: `dotnet test KedrStore.sln --no-build --no-restore --configuration Release` — 111 пройшли, 14 пропущено, 0 збоїв; fixture з урахуванням CI робить три перевірки провайдера обов'язковими за `CI=true`.

## Обов'язковий порядок виконання

1. **Red:** додати тести PostgreSQL на унікальність, обов'язкову батьківську сутність, фізичний каскад, збереження за м'якого видалення й захист від застарілого URL; підтвердити очікувані збої.
2. **Green:** завершити відображення й поведінку запису, потрібні цим тестам.
3. **Refactor:** залишити питання EF в Infrastructure.
4. **Regression:** запустити підмножину інтеграційних тестів збереження Catalog.
5. **Evidence:** записати всі команди й результати.
