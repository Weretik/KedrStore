# API читання категорій — навігація категоріями

## Поведінка

- Клієнт запитує колекцію категорій із `lang=uk` або `lang=ru` й отримує повний ліс кореневих категорій. Кожен вузол містить рекурсивно впорядковані дочірні вузли.
- Клієнт запитує категорію за її публічним `categorySlug` й отримує цю категорію, її рекурсивно впорядкованих нащадків і breadcrumbs від кореня до категорії.
- `name` — це `ShortNameUk` для `uk` і `ShortNameRu` для `ru`. Початкові 1C `Name`, кореневий ключ 1C і технічний `Path` не є полями публічного API.
- Frontend використовує `id` як стабільну ідентичність категорії, а `slug` — для побудови публічних URL категорій. Він не має виводити ідентичність, порядок чи ієрархію з локалізованої назви.

## Правила та інваріанти

- Кожен повернений вузол має додатний цілий `id`, непорожні `slug` і `name`, `sortOrder >= 0`, `level >= 0` та масив `children` (порожній для листків).
- `parentId` дорівнює `null` лише для кореневого вузла. Для некореневого вузла він ідентифікує його безпосереднього батька в повернутому дереві.
- Для кореневих вузлів `level` дорівнює нулю; для інших — кількості ребер від кореня. Це метадані, якими керує backend, а не значення, обчислюване клієнтами.
- Сусіди впорядковуються за зростанням `sortOrder`; за однакових значень — за зростанням `id`.
- Колекція повертає `200` і `[]`, якщо категорії не імпортовано. Запит неіснуючого slug повертає `404` без тіла.
- Некоректний `lang` або порожній/некоректний `categorySlug` повертає усталену відповідь помилки валідації `400`. Ендпоїнти доступні лише для читання й не мають ключа ідемпотентності.

## Сценарії приймання

1. За наявності кореневих і дочірніх категорій із різними значеннями `SortOrder`, коли запитується колекція, кожен список сусідів упорядковується за `SortOrder`, потім за `Id`, а кожні `level` і `parentId` описують ту саму ієрархію.
2. За наявності категорії з короткими назвами українською та російською, коли та сама колекція запитується з `uk` і `ru`, ідентичність вузла, ієрархія, порядок і slug не змінюються, тоді як `name` локалізується.
3. За наявності вкладеної категорії, коли запитується її slug, відповідь містить нащадків вузла та breadcrumbs у порядку від кореня до поточної категорії.
4. За невідомого slug, коли клієнт запитує ендпоїнт окремої категорії, він отримує `404` без даних категорії.
