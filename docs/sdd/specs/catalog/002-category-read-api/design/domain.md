# API читання категорій — проєктування: Domain

## Відповідальність

Поведінка домену не змінюється. `ProductCategory` і далі відповідає за ідентичність категорії, slug, зв’язок із батьківською категорією, локалізовані короткі назви, порядок і рівень. API проєктує наявну модель читання й не має розкривати агрегат/сутність безпосередньо.

## Взаємодія між модулями

API Catalog викликає запити Application Catalog через Mediator. Обробники запитів читають через `ICatalogReadRepository<ProductCategory>` з наявною no-tracking специфікацією та повертають `Ardalis.Result`; вони не публікують події й не змінюють стан. Публічний запит окремої категорії виконує пошук за slug; запит адміністратора окремої категорії — за числовим `ProductCategoryId`. Обидва використовують специфікації Application замість розбору значення маршруту.

## Ризики

Імпорт може оновити дані відображення категорії під час читання запиту. Кожна відповідь відображає стан бази даних на момент читання; у цій фічі немає гарантії актуальності кешу. Некоректна застаріла ієрархія не має спричиняти нескінченну рекурсивну побудову DTO: проєкція Application має виявляти цикли або уникати їх і повертати очікувану помилку з діагностикою замість переповнення стека.
