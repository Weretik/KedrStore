# Замовлення адміністратора та синхронізація з 1C — дизайн: Domain

## Відповідальність

У `Sales.Domain` з'являється агрегат `Order` з інкапсульованими рядками замовлення й обов'язковим `CounterpartyId`. Агрегат відповідає за інваріанти замовлення, незалежні від вхідних даних: непорожню колекцію рядків, додатні кількості, коректні ідентифікатори товарів і незмінний зв'язок ідентичності та контрагента після створення.

`OneCOrderSync` — окремий корінь агрегату Sales, пов'язаний з `Order` один до одного через типізований об'єкт-значення `OrderId` (на основі типу БД `bigint`). Він відповідає лише за переходи стану передавання: кількість спроб, запланований час, кінцеві стани, очищені діагностичні дані й метадані прийняття. Після підтвердженої успішної відповіді він записує номер документа 1C, повернений у `DocId`; локальний `OrderNumber` залишається вихідним ключем ідемпотентності. Запис створюється атомарно із замовленням і безпечно захоплюється фоновим завданням.

Domain не залежить від SOAP, HTTP, EF Core, планувальника або Cloud Run. Для початкового сценарію подія домену не потрібна: довговічний запис `Pending` передає роботу запланованому завданню.

## Взаємодія між модулями

- `CounterpartyId` — імпортований рядковий ідентифікатор 1C, яким володіє Sales. Сценарій створення перевіряє його локальне існування через абстракцію Sales і не запитує дані клієнта з 1C.
- ID товарів зберігаються як зовнішні ідентифікатори, передані адміністративним frontend. Команда створення перевіряє, що вони непорожні; 1C залишається авторитетним джерелом бізнес-перевірки доступності товарів і відхиляє невідомі ідентифікатори як бізнес-помилку.
- `Order.Id` — це `OrderId`, типобезпечний об'єкт-значення Domain на основі технічного типу БД `long`. `Order.OrderNumber` — незмінний читабельний номер (`SO-YYYYMMDD-NNNN`), який генерує Sales і передає до 1C як зовнішній ключ.

## Ризики

- Паралельні обробники не повинні одночасно захоплювати й надсилати той самий запис очікування передавання.
- Можливий збій процесу після отримання запиту в 1C, але до фіксації прийняття в Sales; незмінний `OrderId` і усунення дублікатів у 1C обов'язкові.
- Грошові значення мають узгоджену семантику загальної суми рядка й повинні зберігати точне десяткове значення під час відображення на SOAP.
