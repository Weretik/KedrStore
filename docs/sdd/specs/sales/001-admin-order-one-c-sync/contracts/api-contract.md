# Admin order and 1C synchronization — HTTP and SOAP contract

**Status:** agreed baseline

## Consumers and compatibility

The consumer is the admin frontend used by sales managers. This is a new API surface; it does not change Catalog's anonymous `POST /api/orders` quick-order endpoint. The endpoint is temporarily anonymous by explicit decision; Manager/Admin authorization is required before production use.

## HTTP operation

`POST /api/admin/orders`

Request shape:

```json
{
  "counterpartyId": "000000000",
  "comment": "optional manager comment",
  "lines": [
    {
      "productId": "000000000",
      "quantity": 2,
      "amount": 12500.00
    }
  ]
}
```

Successful response shape:

```json
{
  "orderId": 12345,
  "orderNumber": "SO-20260817-0001",
  "syncStatus": "Pending"
}
```

`orderId` is the database-assigned local `OrderId` (`bigint`). `orderNumber` is the immutable human-readable and 1C external identifier in the `SO-YYYYMMDD-NNNN` format. No separate public UUID is required.

The endpoint is `[AllowAnonymous]` temporarily. Production follow-up: replace it with `[Authorize(Policy = PolicyNames.CanManageOrders)]`; the existing policy permits Manager and Admin roles. The request requires an `Idempotency-Key` header: an opaque UUID generated by the frontend once per create action. The backend stores the key, canonical request hash, and original order result atomically with the order. An identical retry returns `200 OK` with that original result; reusing a key with different request data returns `409 Conflict`. Keys are retained for 24 hours, then safely cleaned up without deleting orders. Expected failures include `400` validation failure, `404` unknown/deleted counterparty, and `409` idempotency conflict. When authorization is enabled, add `401` and `403`. Internal SOAP errors are never returned as raw details.

After agreement, create `docs/sdd/contracts/sales/admin-order-one-c-sync.openapi.yaml` and add its `$ref` to `docs/sdd/contracts/openapi.yaml`.

## Admin order sync-status contract

`GET /api/admin/orders/{orderId}/sync-status` returns the delivery state for one order. It is temporarily `[AllowAnonymous]`; before production it must be protected with `PolicyNames.CanManageOrders` (Manager and Admin). Its response includes only `orderId`, `orderNumber`, `syncStatus`, nullable `oneCDocumentNumber`, and nullable `acceptedAtUtc`. `oneCDocumentNumber` is mapped from `OneCOrderSync.OneCDocumentNumber`; the frontend shows it only after 1C has accepted the order. Internal SOAP diagnostics are never returned.

The versioned OpenAPI contract declares the route, temporary anonymous access, and `200`, `401`, `403`, and `404` responses.

## Manual retry contract

`POST /api/admin/orders/{orderId}/sync/retry` accepts `{ "reason": "..." }` and schedules a new background delivery cycle. It never calls 1C inside the HTTP request. Only `BusinessError` and `DeadLetter` can transition to `RetryScheduled`; an unknown order returns `404`, an invalid reason returns `400`, and every other current status returns `409`. A successful request returns `202` with `orderId`, the unchanged `orderNumber`, and `syncStatus: "RetryScheduled"`.

The transition resets the per-cycle delivery and dead-letter-notification counters. Before that reset, Infrastructure persists an audit record containing the previous status, attempt count, bounded diagnostics, reason, caller identity, and request time in the same database save. PostgreSQL `xmin` prevents two concurrent requests from scheduling the same terminal state twice. The endpoint is temporarily `[AllowAnonymous]` under the existing development decision and records `anonymous-development` when no authenticated identity exists; production must enable `PolicyNames.CanManageOrders` before exposing this operation.

## Existing SOAP operation

No WSDL change is needed. The generated client exposes:

```text
CreateSiteRequest(RequestData) -> RequestDataOut

RequestData:
  CounterpartyId: string
  Comment: string
  OrderId: string
  Date: DateTime
  Items[]: { ProductId: string, Quantity: string, Amount: decimal }

RequestDataOut:
  DocId: string
  Comment: string
```

`RequestData.OrderId` always receives the stable local `OrderNumber`, not the technical GUID. The same number is reused for retries, so a manager can find the 1C document by its displayed number. `Item.Amount` maps from the request line `amount`, which is the total for the complete line quantity. A confirmed created-document `RequestDataOut.DocId` maps to `Accepted` and is saved as `OneCDocumentNumber`; a response whose `DocId` says that the document was not created maps to `BusinessError`, even if it is non-empty. An empty `DocId` returned without SOAP/transport failure also maps to `BusinessError`, using a sanitized bounded `Comment` as diagnostic data.

The future machine-readable OpenAPI document explicitly declares `Idempotency-Key` as a required UUID header parameter, including the successful replay and `409 Conflict` responses.
