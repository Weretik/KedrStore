# Admin order and 1C synchronization — HTTP and SOAP contract

**Status:** agreed baseline

## Consumers and compatibility

The consumer is the admin frontend used by sales managers. This is a new API surface; it does not change Catalog's anonymous `POST /api/orders` quick-order endpoint. The endpoint is temporarily anonymous by explicit decision; Manager/Admin authorization is required before production use.

## HTTP operation

`POST /api/admin/orders`

Request shape:

```json
{
  "counterpartyId": "000000000",
  "comment": "optional manager comment",
  "lines": [
    {
      "productId": "000000000",
      "quantity": 2,
      "amount": 12500.00
    }
  ]
}
```

Successful response shape:

```json
{
  "orderId": "00000000-0000-0000-0000-000000000000",
  "orderNumber": "SO-20260817-0001",
  "syncStatus": "Pending"
}
```

The endpoint is `[AllowAnonymous]` temporarily. The request requires an `Idempotency-Key` header: an opaque UUID generated by the frontend once per create action. The backend stores the key, canonical request hash, and original order result atomically with the order. An identical retry returns `200 OK` with that original result; reusing a key with different request data returns `409 Conflict`. Keys are retained for 24 hours, then safely cleaned up without deleting orders. Expected failures include `400` validation failure, `404` unknown/deleted counterparty, and `409` idempotency conflict. When authorization is enabled, add `401` and `403`. Internal SOAP errors are never returned as raw details.

After agreement, create `docs/sdd/contracts/sales/admin-order-one-c-sync.openapi.yaml` and add its `$ref` to `docs/sdd/contracts/openapi.yaml`.

## Existing SOAP operation

No WSDL change is needed. The generated client exposes:

```text
CreateSiteRequest(RequestData) -> RequestDataOut

RequestData:
  CounterpartyId: string
  Comment: string
  OrderId: string
  Date: DateTime
  Items[]: { ProductId: string, Quantity: string, Amount: decimal }

RequestDataOut:
  DocId: string
  Comment: string
```

`RequestData.OrderId` always receives the stable local `OrderNumber`, not the technical GUID. The same number is reused for retries, so a manager can find the 1C document by its displayed number. `Item.Amount` maps from the request line `amount`, which is the total for the complete line quantity. A non-empty `RequestDataOut.DocId` maps to `Accepted`; an empty `DocId` returned without SOAP/transport failure maps to `BusinessError`, using a sanitized bounded `Comment` as diagnostic data.

The future machine-readable OpenAPI document explicitly declares `Idempotency-Key` as a required UUID header parameter, including the successful replay and `409 Conflict` responses.
