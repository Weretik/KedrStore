# T145 — Jobs: Dead-letter Telegram notification and Excel export

**Depends on:** T010, T020, T040, T100

- [ ] Add `ProductName` to `OrderLine` as the immutable product-name snapshot received during manager order creation; map and persist it with the line so an export does not depend on the current catalog.
- [ ] Define Sales Application contracts for a dead-letter notification and an order Excel export under `src/Sales/Sales.Application/Features/Orders/DeliveryFailure/`. The DTO includes order ID, counterparty name/ID, final sanitized error, and persisted order lines.
- [ ] Implement `Sales.Infrastructure` adapters under `Notifications/` and `Exports/`: send an HTML Telegram message and attach an `.xlsx` file. Reuse the configured Telegram bot connection, but do not depend on Catalog's `CreateOrderRequest`, `ITelegramNotifier`, or `IOrderExcelExporter` contracts.
- [ ] The Telegram caption contains: `DeadLetter` status, local order ID, current counterparty name and ID, final sanitized error, attempt count, and timestamp. Read client data from `Counterparty`; do not create customer snapshots in `Order`. The file contains all lines: product ID, product name, quantity, line amount, and order total.
- [ ] Ensure notification failure is logged and scheduled for safe retry/observability without changing a successfully persisted `DeadLetter` state or re-sending the 1C request.
- [ ] Add tests for Excel content, caption sanitization, a single notification per dead-letter transition, and Telegram transport failure.

## Checkpoint

An undeliverable order is visible to operators in Telegram with sufficient context to act, while the persisted order and its terminal delivery status remain the source of truth.
