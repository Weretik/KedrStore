## Контрольна точка

`dotnet run --project src/Bootstrapper/Host.Jobs/Host.Jobs -- --job=sync-one-c-orders` виконує один безпечний прохід доставки. Те саме завдання надсилає запит і визначає результат прийняття, бізнес-відхилення чи транспортної помилки за поточною відповіддю SOAP.

## Розширення T155

T155 уточнює правило прийняття відповіді: `DocId` приймається лише тоді, коли позначає створений документ 1С. Відповідь про те, що документ не створено, означає `BusinessError`, навіть якщо `DocId` непорожній.

## Примітка щодо обсягу

Поточний контракт SOAP не має окремої операції читання для перевірки раніше створеного документа 1С за `OrderId` чи `DocId`. Тому завдання періодичного опитування не створювали. Якщо 1С згодом додасть таку операцію, слід створити окреме завдання фічі для звіряння, а не неявно змінювати це завдання доставки.
