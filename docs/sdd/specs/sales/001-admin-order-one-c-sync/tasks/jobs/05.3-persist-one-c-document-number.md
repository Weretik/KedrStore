# T155 — Jobs: persist the 1C document number

**Depends on:** T020, T050, T060, T100, T150

- [x] Add nullable `OneCDocumentNumber` to `OneCOrderSync`. Only the aggregate's accepted transition may assign it, from the confirmed successful `ISalesOneCWriteClient` result. It is immutable once assigned.
- [x] Map the field as a nullable string with maximum length 128 in `OneCOrderSyncConfiguration`, generate a new non-destructive Sales EF Core migration, and apply it through the existing migration job. Do not modify the already-applied orders migration. The application uses the existing automatic migration job.
- [x] In `SyncOneCOrdersJob`, persist the returned `OneCDocumentId` together with the `Accepted` transition. A missing identifier or a response indicating that the document was not created must remain `BusinessError` and leave `OneCDocumentNumber` null.
- [x] Add domain, persistence, and job tests proving that an accepted response stores the returned number, failure paths do not store it, and an accepted number cannot be changed by later processing.
- [x] Keep the number available to a future admin order read/status projection. Do not add an HTTP endpoint in this task; its route and contract are a separate API decision.

## Checkpoint

After a successful `CreateSiteRequest`, the same `OneCOrderSync` record contains `Status = Accepted`, `AcceptedAtUtc`, and the bounded 1C document number. The number is safe for a future frontend display and no raw SOAP error is exposed through HTTP.
