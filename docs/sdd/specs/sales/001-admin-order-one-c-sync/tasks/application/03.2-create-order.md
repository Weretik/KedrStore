# T100 — Application: create manager order

**Depends on:** T090, T040

- [ ] Implement `CreateOrderCommandHandler` in `src/Sales/Sales.Application/Features/Orders/Create/`.
- [ ] Require a UUID `Idempotency-Key`, calculate the canonical create-request hash, and use the idempotency store before state changes: return the original result for the same key/hash, return `409 Conflict` for the same key with another hash, or atomically save a new `Order`, `OneCOrderSync`, and 24-hour `OrderIdempotencyRecord`.
- [ ] Validate counterparty ID, non-empty lines, product identifiers, quantities, amount bounds, and comment length before state changes.
- [ ] Load the existing active Sales `Counterparty`; return an expected not-found/invalid result when it is absent or soft-deleted.
- [ ] Generate the database-backed `OrderNumber`, persist the new `Order` so EF Core assigns its typed `OrderId` (`bigint` column), then attach the initial `OneCOrderSync(Pending)` in the same database transaction with `CancellationToken` propagation.
- [ ] Return the local order identifier, `OrderNumber`, and `Pending` delivery status; do not call `ISalesOneCWriteClient` from the request handler.
- [ ] Add validator and handler unit tests for success, invalid payload, unknown counterparty, transaction failure, and duplicate-idempotency behaviour if adopted.

## Checkpoint

The admin HTTP request durably queues an order for delivery and remains independent from immediate 1C availability.
