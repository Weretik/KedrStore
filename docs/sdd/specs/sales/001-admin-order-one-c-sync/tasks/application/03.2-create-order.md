# T100 — Application: створення замовлення менеджера

**Залежить від:** T090, T040

- [x] Реалізувати `CreateOrderCommandHandler` у `src/Sales/Sales.Application/Features/Orders/Create/`.
- [x] Вимагати UUID `Idempotency-Key`, обчислювати канонічний хеш запиту створення й використовувати сховище ідемпотентності до зміни стану: повертати початковий результат для того самого ключа/хешу, `409 Conflict` для того самого ключа з іншим хешем або атомарно зберігати нові `Order`, `OneCOrderSync` і 24-годинний `OrderIdempotencyRecord`.
- [x] До зміни стану перевіряти ID контрагента, непорожні позиції, ідентифікатори товарів, кількості, межі сум і довжину коментаря.
- [x] Завантажувати наявного активного `Counterparty` модуля Sales; повертати очікуваний результат «не знайдено»/«некоректно», якщо його немає або його м'яко видалено.
- [x] Генерувати `OrderNumber` через базу даних, зберігати новий `Order`, щоб EF Core призначив типізований `OrderId` (стовпець `bigint`), а потім додавати початковий `OneCOrderSync(Pending)` у тій самій транзакції БД із передаванням `CancellationToken`.
- [x] Повертати локальний ідентифікатор замовлення, `OrderNumber` і стан передавання `Pending`; не викликати `ISalesOneCWriteClient` з обробника запиту.
- [x] Додати unit-тести валідатора й обробника для успіху, некоректного payload, невідомого контрагента, збою транзакції та повторного запиту з ключем ідемпотентності, якщо цей підхід прийнято.

## Контрольна точка

Адміністративний HTTP-запит надійно ставить замовлення в чергу передавання й не залежить від негайної доступності 1С.
