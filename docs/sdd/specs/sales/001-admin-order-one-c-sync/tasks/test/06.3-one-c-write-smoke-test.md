# T185 — Manual live 1C SOAP write smoke verification

**Status:** Complete. Three accepted writes against the test 1C endpoint are recorded below.

## Purpose

`one-c-smoke-write` is a deliberate manual integration check. Unlike an automated test, it sends a real `CreateSiteRequest` SOAP request and creates a real document in the configured **test** 1C database. Run it only when a test document is acceptable.

## Preconditions

- Run from `src/Bootstrapper/Host.Jobs/Host.Jobs`.
- Set `DOTNET_ENVIRONMENT` to `Development`; only then does Host.Jobs load its local User Secrets.
- Keep `OneCSoap:Endpoint`, `OneCSoap:Username`, and `OneCSoap:Password` in Host.Jobs User Secrets or environment variables. Never put them in this document, `appsettings.json`, command arguments, or logs.
- Use unique test `orderNumber` values so each run can be identified in 1C.

## Command

```powershell
Set-Location C:\Users\Віталій\RiderProjects\KedrStore\src\Bootstrapper\Host.Jobs\Host.Jobs
$env:DOTNET_ENVIRONMENT = 'Development'

dotnet run --project .\Host.Jobs.csproj -- --job=one-c-smoke-write --counterpartyId=000000298 --productId=8190 --quantity=10 --amount=1000 --orderNumber=TEST-SO-YYYYMMDD-NNN --comment='TEST: manual SOAP verification.'
```

Before SOAP transmission, numeric product IDs are left-padded to nine characters: `8190` is sent as `000008190`. The command passes the current UTC date/time to 1C.

## Result interpretation

| Output | Meaning | Next action |
| --- | --- | --- |
| `ENV = Development`, `outcome=Accepted`, a non-empty `documentId`, and `[SUCCESS]` | 1C accepted the request and created its document. | Ask the 1C team to verify the document, lines, quantity, amount, and price in 15–30 minutes. |
| `BusinessError` | 1C received the request but did not create the document. | Read the bounded 1C response diagnostic in the warning log and ask the 1C team to investigate. |
| `TransportError` | The request did not complete at the SOAP transport/configuration layer. | Check `DOTNET_ENVIRONMENT`, Host.Jobs secrets, endpoint reachability, and the exception type. |
| `ENV = Production` on a local run | Local Development User Secrets were not loaded. | Set `$env:DOTNET_ENVIRONMENT = 'Development'` and run again. |

Exit code `0` means `Accepted`; code `3` means `BusinessError` or `TransportError`; code `1` means a host/argument/runtime error.

## Code map

- `src/Bootstrapper/Host.Jobs/Host.Jobs/Program.cs` selects `--job=one-c-smoke-write`, parses the command arguments, builds `OneCOrderDeliveryRequest`, prints the safe result, and returns the exit code.
- `src/Sales/Sales.Infrastructure/Integrations/OneC/SalesOneCWriteClient.cs` maps the application request to SOAP `RequestData`, converts numeric product IDs to nine characters, calls 1C, and maps the reply to `Accepted`, `BusinessError`, or `TransportError`.
- `src/Sales/Sales.Infrastructure/Integrations/OneC/OneCSiteRequestSender.cs` performs the generated SOAP client call.
- `tests/IntegrationTests/SalesOneCWriteClientTests.cs` is the separate automated test suite. It tests mapping, success, 1C business rejection, and transport failures without calling a real 1C server or creating documents.

## Follow-up structure

The manual command currently has a small argument parser in `Program.cs`; that is acceptable for a single diagnostic command. If additional manual Sales commands appear, extract it into a dedicated `OneCSmokeWriteJob` class with focused unit tests instead of growing `Program.cs` further.

## Checkpoint

The live smoke test is reproducible without exposing secrets. Its successful 1C document number provides evidence that the configured test 1C accepted the SOAP write, while automated tests continue to cover deterministic behavior without external side effects.
