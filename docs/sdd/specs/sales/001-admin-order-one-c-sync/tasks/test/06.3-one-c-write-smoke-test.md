# T185 — Ручна smoke-перевірка реального SOAP-запису в 1C

**Статус:** Завершено. Нижче зафіксовано три прийняті записи до тестового endpoint 1C.

## Призначення

`one-c-smoke-write` — свідома ручна інтеграційна перевірка. На відміну від автоматизованого тесту, вона надсилає справжній SOAP-запит `CreateSiteRequest` і створює справжній документ у налаштованій **тестовій** базі 1C. Запускайте її лише тоді, коли створення тестового документа допустиме.

## Передумови

- Запускайте з `src/Bootstrapper/Host.Jobs/Host.Jobs`.
- Установіть `DOTNET_ENVIRONMENT` у `Development`; лише тоді Host.Jobs завантажить локальні User Secrets.
- Зберігайте `OneCSoap:Endpoint`, `OneCSoap:Username` і `OneCSoap:Password` у User Secrets Host.Jobs або змінних середовища. Ніколи не записуйте їх у цей документ, `appsettings.json`, аргументи команд або логи.
- Використовуйте унікальні тестові значення `orderNumber`, щоб кожен запуск можна було знайти в 1C.

## Команда

```powershell
# Із кореня репозиторію KedrStore:
Set-Location .\src\Bootstrapper\Host.Jobs\Host.Jobs
$env:DOTNET_ENVIRONMENT = 'Development'

dotnet run --project .\Host.Jobs.csproj -- --job=one-c-smoke-write --counterpartyId=000000298 --productId=8190 --quantity=10 --amount=1000 --orderNumber=TEST-SO-YYYYMMDD-NNN --comment='TEST: manual SOAP verification.'
```

Перед передаванням SOAP числові ID товарів доповнюються нулями зліва до дев'яти символів: `8190` надсилається як `000008190`. Команда передає до 1C поточні дату й час UTC.

## Тлумачення результату

| Вивід | Значення | Наступна дія |
| --- | --- | --- |
| `ENV = Development`, `outcome=Accepted`, непорожній `documentId` і `[SUCCESS]` | 1C прийняла запит і створила документ. | Попросіть команду 1C перевірити документ, рядки, кількість, суму й ціну протягом 15–30 хвилин. |
| `BusinessError` | 1C отримала запит, але не створила документа. | Прочитайте обмежену діагностику відповіді 1C у журналі попереджень і попросіть команду 1C дослідити причину. |
| `TransportError` | Запит не завершився на рівні SOAP-транспорту або конфігурації. | Перевірте `DOTNET_ENVIRONMENT`, секрети Host.Jobs, доступність endpoint і тип винятку. |
| `ENV = Production` під час локального запуску | Локальні Development User Secrets не завантажилися. | Установіть `$env:DOTNET_ENVIRONMENT = 'Development'` і запустіть знову. |

Код завершення `0` означає `Accepted`; код `3` — `BusinessError` або `TransportError`; код `1` — помилку хоста, аргументів або виконання.

## Зафіксовані успішні перевірки

| Дата | Локальний номер замовлення | Номер документа 1C | Результат |
| --- | --- | --- | --- |
| 2026-08-18 | `TEST-SO-20260818-001` | `Наш-005859` | Accepted |
| 2026-08-21 | `TEST-SO-20260821-002` | `Наш-005861` | Accepted |
| 2026-08-21 | `TEST-SO-20260821-003` | `Наш-005862` | Accepted |

Ці запуски перевіряють реальний тестовий endpoint, секрети, відображення SOAP-запиту, нормалізацію ID товарів до дев'яти символів та обробку відповіді 1C. Вони не замінюють бізнес-перевірку створеного документа командою 1C.

## Карта коду

- `src/Bootstrapper/Host.Jobs/Host.Jobs/Program.cs` обирає `--job=one-c-smoke-write`, розбирає аргументи команди, створює `OneCOrderDeliveryRequest`, виводить безпечний результат і повертає код завершення.
- `src/Sales/Sales.Infrastructure/Integrations/OneC/SalesOneCWriteClient.cs` відображає application-запит у SOAP `RequestData`, перетворює числові ID товарів на дев'ятисимвольні, викликає 1C і відображає відповідь у `Accepted`, `BusinessError` або `TransportError`.
- `src/Sales/Sales.Infrastructure/Integrations/OneC/OneCSiteRequestSender.cs` виконує виклик згенерованого SOAP-клієнта.
- `tests/IntegrationTests/SalesOneCWriteClientTests.cs` — окремий набір автоматизованих тестів. Він перевіряє відображення, успіх, бізнес-відхилення 1C і транспортні збої без виклику реального сервера 1C чи створення документів.

## Подальша структура

Наразі ручна команда має невеликий парсер аргументів у `Program.cs`; це прийнятно для однієї діагностичної команди. Якщо з'являться додаткові ручні команди Sales, винесіть його в окремий клас `OneCSmokeWriteJob` із цільовими unit-тестами замість подальшого збільшення `Program.cs`.

## Контрольна точка

Реальний smoke-тест можна повторити без розкриття секретів. Номер документа 1C у разі успіху підтверджує, що налаштована тестова 1C прийняла SOAP-запис, а автоматизовані тести й далі покривають детерміновану поведінку без зовнішніх побічних ефектів.
