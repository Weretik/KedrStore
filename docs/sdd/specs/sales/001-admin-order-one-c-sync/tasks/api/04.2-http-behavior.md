# T120 — API: HTTP behavior, authorization, and idempotency

**Depends on:** T110

- [ ] Create request/response DTOs under `src/Sales/Sales.Api/Contracts/Orders/` if they differ from Application DTOs.
- [ ] Mark the endpoint `[AllowAnonymous]` as the temporary agreed access decision. Add an explicit production follow-up to replace it with `PolicyNames.CanManageOrders`; it permits Manager and Admin roles and requires no new role or policy.
- [ ] Require a UUID `Idempotency-Key` HTTP header and map it to the creation command. An identical repeat within the 24-hour retention window returns the original `200 OK` result; a key reused with different request data returns `409 Conflict`.
- [ ] Declare `ProducesResponseType` metadata for success, validation failure, unauthorized, forbidden, missing counterparty, and idempotency conflict as applicable.
- [ ] Confirm the endpoint never returns SOAP diagnostic details or persistence entities.

## Checkpoint

The endpoint follows the temporary anonymous-access decision, has an explicit production authorization follow-up, and has documented repeated-request behaviour.
