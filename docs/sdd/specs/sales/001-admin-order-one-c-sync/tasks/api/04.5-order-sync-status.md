# T135 — API: читання стану синхронізації замовлення адміністратора

**Залежить від:** T120, T130, T150, T155

## Погоджене рішення

`GET /api/admin/orders/{orderId}/sync-status` тимчасово має `[AllowAnonymous]`. До production замініть його на `PolicyNames.CanManageOrders` (Manager і Admin).

- [x] Додати тимчасово анонімний endpoint стану одного замовлення за погодженим маршрутом. Він отримує стан через запит Application; контролер не повинен напряму читати EF Core.
- [x] Додати запит Application і DTO результату, які повертають лише `orderId`, `orderNumber`, `syncStatus`, nullable `oneCDocumentNumber` і nullable `acceptedAtUtc`.
- [x] Повертати `404 Not Found`, коли замовлення не існує. До прийняття передавання повертати `oneCDocumentNumber: null` і `acceptedAtUtc: null`. Ніколи не повертати необроблені SOAP-відповіді, діагностику 1С, облікові дані чи payload запиту.
- [x] Оновити версіонований OpenAPI-документ і `contracts/api-contract.md` погодженим маршрутом, авторизацією, схемою відповіді й поведінкою `200`, `401`, `403` та `404`.
- [x] Додати HTTP-інтеграційні тести для станів очікування, прийняття, бізнес-помилки й відсутнього замовлення. Перевірити, що прийняте замовлення відкриває збережений номер документа 1С, а внутрішні деталі SOAP відсутні у відповіді.

## Контрольна точка

Frontend може запитати поточний стан передавання Sales для одного замовлення. `syncStatus = Accepted` і ненульовий `oneCDocumentNumber` означають, що 1С прийняла й створила документ; інші стани й нульовий номер означають, що створення в 1С не підтверджено.
