# T135 — API: admin order sync-status read API

**Depends on:** T120, T130, T150, T155

## Agreed decision

`GET /api/admin/orders/{orderId}/sync-status` is temporarily `[AllowAnonymous]`. Before production, replace it with `PolicyNames.CanManageOrders` (Manager and Admin).

- [x] Add a temporarily anonymous single-order status endpoint using the agreed route. It obtains the status through an Application query; the controller must not read EF Core directly.
- [x] Add an Application query and result DTO that return only `orderId`, `orderNumber`, `syncStatus`, nullable `oneCDocumentNumber`, and nullable `acceptedAtUtc`.
- [x] Return `404 Not Found` when the order does not exist. Return `oneCDocumentNumber: null` and `acceptedAtUtc: null` until delivery is accepted. Never return raw SOAP responses, 1C diagnostics, credentials, or request payloads.
- [x] Update the versioned OpenAPI document and `contracts/api-contract.md` with the agreed route, authorization, response schema, `200`, `401`, `403`, and `404` behaviour.
- [x] Add HTTP integration tests for pending, accepted, business-error, and missing-order cases. Assert that an accepted order exposes the saved 1C document number and that no internal SOAP details appear in the response.

## Checkpoint

The frontend can request the current Sales delivery state for one order. `syncStatus = Accepted` and a non-null `oneCDocumentNumber` mean that 1C has accepted and created the document; other statuses and a null number mean it has not been confirmed as created in 1C.
