# T135 — API: admin order sync-status read API

**Depends on:** T120, T130, T150, T155

## Required decision before implementation

**[NEEDS CLARIFICATION: approve the route and access rule recorded in `contracts/api-contract.md`. Do not implement this task until that decision is made.]**

- [ ] Add a protected single-order status endpoint using the agreed route. It obtains the status through an Application query; the controller must not read EF Core directly.
- [ ] Add an Application query and result DTO that return only `orderId`, `orderNumber`, `syncStatus`, nullable `oneCDocumentNumber`, and nullable `acceptedAtUtc`.
- [ ] Return `404 Not Found` when the order does not exist. Return `oneCDocumentNumber: null` and `acceptedAtUtc: null` until delivery is accepted. Never return raw SOAP responses, 1C diagnostics, credentials, or request payloads.
- [ ] Update the versioned OpenAPI document and `contracts/api-contract.md` with the agreed route, authorization, response schema, `200`, `401`, `403`, and `404` behaviour.
- [ ] Add HTTP integration tests for pending, accepted, business-error, and missing-order cases. Assert that an accepted order exposes the saved 1C document number and that no internal SOAP details appear in the response.

## Checkpoint

The frontend can request the current Sales delivery state for one order. `syncStatus = Accepted` and a non-null `oneCDocumentNumber` mean that 1C has accepted and created the document; other statuses and a null number mean it has not been confirmed as created in 1C.
