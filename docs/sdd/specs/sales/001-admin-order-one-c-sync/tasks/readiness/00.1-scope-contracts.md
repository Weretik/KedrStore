# Subphase 00.1 — Readiness: confirm implementation baseline

- [x] T001 Confirmed: `Item.Amount` is the total amount for the complete order line, not a unit price. For example, if `Quantity = 10`, `Amount` is the total for those 10 units.
- [x] T001a Established the initial integration rule: a non-empty `RequestDataOut.DocId` means `Accepted`; an empty `DocId` returned without a SOAP/transport failure means `BusinessError`; `Comment` is stored only as sanitized, bounded diagnostic text.
- [x] T002 Confirmed initial settings: `MaxAttempts=10`, batch size `20`, delay `5 seconds`, sending window `07:00–20:00 Europe/Kyiv`, and retry schedule `5m → 15m → 30m → 60m → 3h`.
- [x] T003 Confirmed the initial HTTP route: `POST /api/admin/orders`. It is deliberately `[AllowAnonymous]` as a temporary decision; before production, replace this with manager/admin authorization in a separate security task.
- [x] T003a Confirmed: `Idempotency-Key` is required by the admin API contract. The frontend generates and reuses it for a retry of the same action; Sales stores it and returns the existing order result for an identical retry. Reusing a key with different request data returns `409 Conflict`.
- [x] T004 Confirmed the initial CQRS boundary: create and persist the manager order, then deliver it through scheduled `SyncOneCOrdersJob`. List, get-by-id, client order history, status-view API, update, cancellation, and manual resend are excluded and will be a separate future feature.
