# Підетап 00.1 — Підготовка: підтвердити основу реалізації

- [x] T001 Підтверджено: `Item.Amount` — загальна сума всього рядка замовлення, а не ціна одиниці. Наприклад, якщо `Quantity = 10`, `Amount` — сума за всі 10 одиниць.
- [x] T001a Встановлено початкове правило інтеграції: непорожній `RequestDataOut.DocId` означає `Accepted`; порожній `DocId`, отриманий без помилки SOAP чи транспорту, означає `BusinessError`; `Comment` зберігається лише як очищений та обмежений за довжиною діагностичний текст.
- [x] T002 Підтверджено початкові налаштування: `MaxAttempts=10`, розмір пакета `20`, пауза `5 seconds`, вікно надсилання `07:00–20:00 Europe/Kyiv` і графік повторів `5m → 15m → 30m → 60m → 3h`.
- [x] T003 Підтверджено початковий маршрут HTTP: `POST /api/admin/orders`. Тимчасовим рішенням для нього свідомо обрано `[AllowAnonymous]`; перед запуском у виробництві слід запровадити авторизацію менеджера/адміністратора в окремому завданні безпеки.
- [x] T003a Підтверджено: контракт адміністративного API вимагає `Idempotency-Key`. Frontend генерує його й повторно використовує для повтору тієї самої дії; Sales зберігає ключ і повертає результат наявного замовлення для ідентичного повтору. Повторне використання ключа з іншими даними запиту повертає `409 Conflict`.
- [x] T004 Підтверджено початкову межу CQRS: створити й зберегти замовлення менеджера, після чого доставити його за розкладом через `SyncOneCOrdersJob`. Список, отримання за ID, історія замовлень клієнта, оновлення й скасування залишаються поза обсягом. Згодом T135 розширило обсяг переглядом стану синхронізації, а T136 — ручним повтором з аудитом із кінцевих станів помилки.

## Контрольна точка

Основу реалізації підтверджено. Дослідження інструментів окремо завершено в `00.2-tooling.md`.
