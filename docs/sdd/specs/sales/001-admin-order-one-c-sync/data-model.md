# Замовлення адміністратора та синхронізація з 1C — модель даних

## Контекст

Sales потребує надійного збереження замовлення менеджера й стану передавання, щоб передавання тривало після завершення HTTP-запиту, перезапуску процесу, масштабування Cloud Run до нуля та тимчасових збоїв 1C.

## Модель

```text
Counterparty (наявний агрегат Sales; Id = ID контрагента в 1C)
└── 1..* Order
    ├── Id (OrderId: типізований об'єкт-значення на основі long; первинний ключ БД bigint)
    ├── OrderNumber (унікальний читабельний номер, наприклад SO-YYYYMMDD-NNNN; зовнішній ключ 1C)
    ├── CounterpartyId (обов'язковий FK/логічне посилання)
    ├── CreatedAtUtc
    ├── Comment (необов'язковий; точні правила ще не визначено)
    └── 1..* OrderLine
        ├── ProductId (обов'язковий зовнішній ідентифікатор 1C/catalog)
        ├── ProductName (обов'язковий знімок для файлу Excel у сповіщенні про помилку)
        ├── Quantity (додатне ціле число)
        └── Amount (загальна сума всього рядка; decimal(18,2))

Order
└── 1..1 OneCOrderSync
    ├── Id (OneCOrderSyncId: типізований об'єкт-значення на основі long; первинний ключ БД bigint)
    ├── OrderId (типізований, унікальний)
    ├── Status
    ├── AttemptCount
    ├── NextAttemptAtUtc
    ├── LastAttemptAtUtc
    ├── LastHttpStatus
    ├── LastErrorCode / LastErrorMessage
    ├── OneCRequestPayloadHash
    ├── OneCResponseBody (очищений і з обмеженням довжини)
    ├── OneCDocumentNumber (рядок, що може бути null, максимум 128; `DocId` 1C лише після прийняття передавання)
    └── AcceptedAtUtc

OrderIdempotencyRecord (запис зберігання Infrastructure, а не сутність Domain)
├── IdempotencyKey (непрозорий UUID клієнта, унікальний у межах операції створення замовлення)
├── RequestHash (обов'язковий; порівняння без зберігання необробленого запиту)
├── OrderId (обов'язкова колонка EF типу long, унікальне посилання на Order; запис лише для зберігання)
├── CreatedAtUtc
└── ExpiresAtUtc (очищення після 24 годин зберігання)
```

OrderSyncRetryAudit (запис аудиту Infrastructure)
- OneCOrderSyncId / OrderId / OrderNumber
- PreviousStatus / PreviousAttemptCount
- PreviousErrorCode / PreviousErrorMessage
- Reason / RequestedBy / RequestedAtUtc

## Інваріанти та цілісність

- Під час створення `Order.CounterpartyId` посилається на одного наявного контрагента Sales, не позначеного як видалений.
- `Order.OrderNumber` унікальний і незмінний. Після призначення базою даних технічного `OrderId` Sales у тій самій транзакції призначає `SO-YYYYMMDD-{OrderId}`; окрема щоденна послідовність не потрібна.
- Замовлення зберігає лише `CounterpartyId`; `Counterparty.Name`, телефон та електронна адреса ніколи не дублюються як знімки замовлення. Єдиним джерелом цих даних залишається Counterparty.
- `OrderLine` має непорожній ідентифікатор товару, знімок назви товару й додатну кількість; замовлення не може не містити рядків.
- `OneCOrderSync.OrderId` унікальний, тож кожне замовлення має один життєвий цикл передавання.
- `OneCOrderSync.OneCDocumentNumber` дорівнює `null`, доки 1C не прийме передавання. Після прийняття він зберігає очищений `RequestDataOut.DocId` з обмеженням довжини; цей ідентифікатор не генерується Sales і ніколи не замінюється під час повтору.
- `OrderIdempotencyRecord.IdempotencyKey` унікальний для операції створення замовлення. Повторний ключ приймається лише за збігу `RequestHash`; інакше команда створення повертає конфлікт.
- Створення зберігає `Order`, `OneCOrderSync` і `OrderIdempotencyRecord` в одній транзакції. Завдання очищення може видаляти прострочені записи ідемпотентності після 24 годин, але ніколи не повинне видаляти замовлення чи запис синхронізації.
- `Status` обмежено задокументованим набором станів; автоматичний повтор не може перевести кінцеві стани прийняття/`DeadLetter` в очікування.
- Для вибору записів, термін яких настав, потрібен індекс, придатний для `Status` і `NextAttemptAtUtc`; захоплення має бути безпечним за конкурентного виконання.
- Текст помилки й тіло відповіді мають явні обмеження довжини та очищуються. Дані запиту представлені лише нечутливим хешем.
- `Amount` — загальна сума всього рядка, що зберігається як `decimal(18,2)`. Рядки з однаковим товаром залишаються окремими, оскільки зберігають введені менеджером дані; відображення на 1C надсилає їх як окремі елементи SOAP `Item`.
- Замовлення використовують обмежувальний зв'язок зовнішнього ключа з Counterparty; контрагента із замовленнями не можна фізично видалити. Фільтрація позначених як видалені в Sales запобігає створенню нових замовлень для видаленого контрагента.
- Кожен ручний повтор додає рядок `OrderSyncRetryAudit` перед скиданням поточного циклу передавання. Рядок аудиту має обмежувальний зовнішній ключ до `OneCOrderSync` і зберігається разом з історією замовлення.
