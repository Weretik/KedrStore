# Граф задач

1. **EN-001 — Контракт і доступ.** Зафіксувати OpenAPI, статуси, quote fingerprint та фактичне мапування `CanManageOrders`; контрактна валідація замінює test-first для документа.
2. **TS-001 — Серверна ціна.** Додати читання політики вибраного клієнта й цін Catalog, quote handler та цільові тести валідних/невалідних позицій і зміни ціни. Red → Green → Refactor → regression/evidence.
3. **TS-002 — Створення.** Додати окремий Admin create endpoint з повторним розрахунком, fingerprint і атомарною ідемпотентністю; цільові domain/application/API тести.
4. **TS-003 — Читання.** Додати список, пошук, фільтр, whitelist sorting і деталі; SQL/інтеграційні тести для `totalRecords`, multiword, стабільних сторінок; виміряти план запиту та додати індекс лише за доказом.
5. **TS-004 — Документація й перевірка.** Звірити OpenAPI з кодом, доповнити Sales feature й індекси, виконати лише потрібні цільові автоматичні перевірки. Занести команди й результати у delivery evidence.

Залежність: EN-001 → TS-001 → TS-002; EN-001 → TS-003; усі → TS-004. Чернетки [005](../../005-admin-order-drafts/README.md) можуть використовувати TS-001 для попереднього розрахунку, але не створюють Order.
