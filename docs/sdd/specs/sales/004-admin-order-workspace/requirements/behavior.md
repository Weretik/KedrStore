# Правила й приймальні сценарії

## Правила

- **R-001.** Список містить лише оформлені Sales Orders, а не чернетки. Сервер застосовує умови, сортування й `totalRecords` до `Skip/Take`; сторінка 1/20 за замовчуванням, максимум 100.
- **R-002.** Пошук без зовнішнього сервісу: trim, нормалізація пробілів, регістронезалежні токени; кожен токен має входити в номер замовлення або назву клієнта, токени поєднані AND. Числовий запит також може збігатися з точним внутрішнім `orderId`. `counterpartyId` — окремий точний фільтр, який поєднується з пошуком через AND.
- **R-003.** Дозволені порядки: `-createdAt` (типовий), `createdAt`, `orderNumber`, `-orderNumber`, `customerName`, `-customerName`, `totalAmount`, `-totalAmount`; останній ключ — `orderId` для стабільної пагінації.
- **R-004.** Список повертає компактні рядки, деталі — збережені позиції, суму, клієнта й безпечний стан 1C; читання не запускає інтеграцію.
- **R-005.** Розрахунок ціни виконує сервер за поточними цінами Catalog і ціновими правилами вибраного Counterparty. Клієнт надсилає лише товар і кількість; відсутня ціна, неіснуючий чи недоступний товар, неактивний клієнт, нульова/від’ємна кількість й переповнення суми дають помилку валідації. Ручне редагування ціни неможливе. Сума відповіді є попереднім розрахунком; на оформленні ціни перераховуються.
- **R-006.** Успішне оформлення атомарно створює Order, позиції зі знімком серверної ціни, номер та `OneCOrderSync(Pending)`; наявний job далі обробляє замовлення. Запит має `Idempotency-Key`: той самий ключ і тіло повертають той самий результат, інше тіло — конфлікт. При помилці часткового замовлення/синхронізації не існує.
- **R-007.** Нові операції доступні лише користувачу з `CanManageOrders`; чинний анонімний контракт не розширюється. Не передавати в журнал тіло замовлення чи дані клієнта.

## Сценарії

- **SC-001:** Given є замовлення різних клієнтів, When Admin шукає частину номера або кілька слів назви й обирає клієнта, Then бачить правильні рядки, `totalRecords` і стабільні сторінки.
- **SC-002:** Given існує замовлення, When Admin відкриває деталі, Then бачить збережені позиції, загальну суму й стан 1C без зміни цих даних; невідомий ID дає 404.
- **SC-003:** Given обрано клієнта й товари, When Admin запитує розрахунок, Then сервер повертає ціни за правилами цього клієнта й пояснює помилкові позиції без створення Order.
- **SC-004:** Given розрахунок був успішний, When між ним і оформленням ціна змінюється, Then оформлення повторно розраховує й зберігає актуальну серверну суму; UI має показати підтвердження актуальної суми до повторного оформлення.
- **SC-005:** Given валідні клієнт і позиції, When Admin оформлює з ключем ідемпотентності, Then є один Order з номером і `Pending` sync; повтор запиту не дублює його.
- **SC-006:** Given ID товару/клієнта некоректний або ціна відсутня, When Admin оформлює, Then отримує 400/404 з безпечними помилками полів, без записів Order.
