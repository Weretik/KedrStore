# API читання замовлень менеджера — граф задач

Визначення сценаріїв наведено у [вимогах до читання замовлень](../requirements/order-reading.md). EN-001–EN-003 і TS-001–TS-006 завершено; докладні докази записано у файлі кожної задачі.

## Оркестратори фаз

1. [Фаза 00 — готовність](00-readiness.md)
2. [Фаза 01 — Domain](01-domain.md)
3. [Фаза 02 — Infrastructure](02-infrastructure.md)
4. [Фаза 03 — Application](03-application.md)
5. [Фаза 04 — API](04-api.md)
6. [Фаза 05 — перевірка](05-verification.md)

Номери фаз упорядковують відповідальність за задачі. Фактичне виконання йде за зв'язками «Залежить від» в такому порядку:

```text
EN-001
├── EN-002 → TS-001 ─┬→ TS-002 ─┐
│                    └→ TS-003 ─┤
└── EN-003 ─────────────────────┴→ TS-004 → TS-005 → TS-006
```

Після EN-001 задачі EN-002 та EN-003 можна виконувати паралельно. Після TS-001 задачі TS-002 та TS-003 можна виконувати паралельно. TS-004 починається лише після завершення обох запитів Application і контракту OpenAPI.

У кожній задачі `TS-*`, що реалізує поведінку, дотримуйтеся такого обов'язкового порядку:

```text
написати цільовий тест → запустити й підтвердити очікуваний Red → реалізувати мінімальну поведінку
→ запустити й підтвердити Green → виконати рефакторинг → запустити регресію → зафіксувати докази
```
