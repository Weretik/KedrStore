# Catalog attributes

**Static code check:** 2026-11-06 (spec 009). **Module:** Catalog.

Product attributes (color, size, side, type, material, …), their dictionary, and the review state of each product. Phases 1–4 of the [attributes SDD](../../specs/catalog/006-attributes-variants-filters/README.md): data model, import, variant groups, the admin API, and the .NET recognizer. Groups are the site models of [spec 007](../../specs/catalog/007-site-models/README.md) (stage 2: status, axes, texts, health, admin API); the public model API of stage 5 is in [public site models](public-site-models.md).

## Structure and relationships

[ImportCatalogAttributesJob](../../../../src/Modules/Catalog/Catalog.Application/Features/Attributes/Jobs/ImportCatalogAttributesJob.cs) reads the [dictionary file](../../../../src/Modules/Catalog/Catalog.Application/Features/Attributes/Shared/Import/AttributeDictionaryFile.cs) and the [recognizer CSV](../../../../src/Modules/Catalog/Catalog.Application/Features/Attributes/Shared/Import/AttributeCsvFile.cs), then syncs attributes, values, and aliases by code, product values and reviews by product, and offers category filters. [AttributeImportCatalog](../../../../src/Modules/Catalog/Catalog.Application/Features/Attributes/Shared/Import/AttributeImportCatalog.cs) holds the built-in settings (kind, unit, URL slug, filterable, variant axis).

[RecognizeCatalogAttributesJob](../../../../src/Modules/Catalog/Catalog.Application/Features/Attributes/Jobs/RecognizeCatalogAttributesJob.cs) recognizes current 1C names with [ProductAttributeRecognizer](../../../../src/Modules/Catalog/Catalog.Application/Features/Attributes/Shared/Recognition/ProductAttributeRecognizer.cs), the port of `extract_attributes.py` v2.0, which gives the same row as the CSV. The [dictionary](../../../../src/Modules/Catalog/Catalog.Application/Features/Attributes/Shared/Recognition/RecognitionDictionary.cs) is the embedded `dictionaries.json` with the owner's code decisions on top. Both the import and the recognizer store rows through [RecognizedProductWriter](../../../../src/Modules/Catalog/Catalog.Application/Features/Attributes/Shared/Import/RecognizedProductWriter.cs); the recognizer's source is `parser`. It runs at the end of the full 1C sync and, for the products that contain a code, after the owner decides that code.

[ProductGroupBuilder](../../../../src/Modules/Catalog/Catalog.Application/Features/Groups/Shared/ProductGroupBuilder.cs) runs at the end of the import and after every admin group change. Products with the same base name ([ProductGroupKey](../../../../src/Modules/Catalog/Catalog.Application/Features/Groups/Shared/ProductGroupKey.cs)) in one category form a [ProductGroup](../../../../src/Modules/Catalog/Catalog.Domain/Groups/ProductGroup.cs) when there are at least two, and an on-site product left alone gets a one-product group. Every group it makes is a proposed site model; accepted models are never changed (their products are pinned and their key is cleared). No name and deleted products never join automatically, and rows a person pinned ([ProductGroupMember](../../../../src/Modules/Catalog/Catalog.Domain/Groups/ProductGroupMember.cs)) are never moved. The main product stays while it is on the site; otherwise the builder takes the best one (on the site, with a photo, in stock, smallest 1C code). Variants that color, size, and side do not tell apart get the review reason `same_variants` («Однакові варіанти»), which the import keeps.

Admin API ([contract](../../contracts/catalog/product-groups.openapi.yaml), policy CanManageProducts; group slug Admin or Seo only): [AdminProductGroups endpoints](../../../../src/Modules/Catalog/Catalog.Api/Endpoints/Groups/GroupsEndpoints.cs) for groups and `GET/PUT /api/admin/products/{id}/group` in [AdminProducts endpoints](../../../../src/Modules/Catalog/Catalog.Api/Endpoints/Products/ProductsEndpoints.cs) for one product.

Site models API ([contract](../../contracts/catalog/site-models.openapi.yaml), policy CanManageProducts): [AdminSiteModels endpoints](../../../../src/Modules/Catalog/Catalog.Api/Endpoints/SiteModels/SiteModelsEndpoints.cs) lists, creates, accepts, and edits models (axes, products, texts, «Заповнити з назв»), and serves «Вітрина сайту» (one row per model with its on-site products, or per product in no model; `status` keeps proposed, accepted, or no-model rows for the review queue) and its category tree (shown categories with on-site products, counts with subcategories, plus each category's own filter count). A product of a proposed model is review work, not `no_model` (spec 007 R-20). On site means exported from 1C, not deleted, and in a category shown on the site (spec 007 R-18). [SiteModelStateReader](../../../../src/Modules/Catalog/Catalog.Application/Features/SiteModels/Shared/SiteModelStateReader.cs) loads models, products, confirmed axis values, and texts; [SiteModelState](../../../../src/Modules/Catalog/Catalog.Application/Features/SiteModels/Shared/SiteModelState.cs) offers axes and counts the problems of on-site products and accepted models ([codes](../../../../src/Modules/Catalog/Catalog.Application/Features/SiteModels/Shared/SiteModelProblems.cs)), which also reach «Огляд»; [SiteModelChanges](../../../../src/Modules/Catalog/Catalog.Application/Features/SiteModels/Shared/SiteModelChanges.cs) checks categories and pins products.

Admin attributes API ([contract](../../contracts/catalog/attributes.openapi.yaml)): [AdminProductAttributes endpoints](../../../../src/Modules/Catalog/Catalog.Api/Endpoints/ProductAttributes/ProductAttributesEndpoints.cs) serves the «Властивості» panel of a product (Manager and Admin: manual values, «Повернути автоматичне», «Прийняти як є», «Повернути на перевірку»); [AdminCatalogAttributes endpoints](../../../../src/Modules/Catalog/Catalog.Api/Endpoints/Attributes/AttributesEndpoints.cs) serves the «Ознаки» page, formerly «Властивості» (Manager reads; Admin adds attributes of their own («Нова ознака», manual, so the import leaves them; type `yesno` «Так / Ні» is a list created with the values «Так» and «Ні») and changes attributes, values, codes, and category filters). «Не розшифровані коди» (spec catalog/008): `GET codes/{aliasId}/products` ([handler](../../../../src/Modules/Catalog/Catalog.Application/Features/Attributes/Queries/GetCodeProducts/GetCodeProductsHandler.cs)) lists on-site products whose names contain the code by category; `PUT codes/{aliasId}` decodes it for all products and/or per category ([AttributeAliasCategoryValue](../../../../src/Modules/Catalog/Catalog.Domain/Attributes/AttributeAliasCategoryValue.cs)); the recognizer takes the category decoding first. A decoding may be several «ознака → значення» pairs in any attributes (spec catalog/009, [AttributeAliasMeaning](../../../../src/Modules/Catalog/Catalog.Domain/Attributes/AttributeAliasMeaning.cs)): the recognition job adds the other attributes' values to the products where the recognizer found the code ([CodeMeanings](../../../../src/Modules/Catalog/Catalog.Application/Features/Attributes/Shared/Import/CodeMeanings.cs)). A value's swatch is a color or a picture: `POST swatches` ([handler](../../../../src/Modules/Catalog/Catalog.Application/Features/Attributes/Commands/UploadAttributeSwatch/UploadAttributeSwatchHandler.cs), [storage](../../../../src/Modules/Catalog/Catalog.Infrastructure/Adapters/Media/AttributeSwatchStorage.cs)) puts the picture on the CDN under `swatches/` and in the library folder «Кольори», and the value is saved with its ID; migration `CatalogColorSwatches` filled the colors of plain and metal finishes that had no swatch. The admin product list filters by problems ([AdminProductProblems](../../../../src/Modules/Catalog/Catalog.Application/Features/Products/Shared/AdminProductProblems.cs)) and the «Огляд» counts them.

[ProductAttributeValue](../../../../src/Modules/Catalog/Catalog.Domain/Attributes/ProductAttributeValue.cs) refuses automatic changes when a person set or locked the value and keeps the latest automatic value for «Повернути автоматичне». [ProductAttributeReview](../../../../src/Modules/Catalog/Catalog.Domain/Attributes/ProductAttributeReview.cs) keeps the base name and reasons; an accepted review stays accepted until a person reopens it. Original 1C names are never changed.

## Code structure

```text
src/Modules/Catalog/
├── Catalog.Domain/Entities/
│   ├── Attributes/  # attribute, value, alias, category filter, product value, review
│   └── Groups/      # model (variant group), the group of each product, model axes and texts
├── Catalog.Application/
│   ├── Attributes/Import/  # file readers, built-in attribute settings, writer shared with the recognizer
│   ├── Attributes/Recognition/  # .NET port of the recognizer (dictionary, observations, base name, row)
│   ├── Groups/             # group builder, key, report
│   ├── Features/Groups/    # admin queries and commands (picker, group, move, create, rename, main)
│   ├── Features/SiteModels/  # site models: list, card, create, accept, axes, products, texts, fill, health
│   ├── Features/ProductAttributes/  # product panel: values, revert, review decisions
│   ├── Features/Attributes/         # «Властивості»: attributes, values, codes, category filters, reasons
│   └── Jobs/Attributes/  # import (CSV) and recognition (1C names) jobs, report
├── Catalog.Api/Endpoints/{Groups,SiteModels,ProductAttributes,Attributes}/  # one group per tag, one endpoint per use case
└── Catalog.Infrastructure/Configurations/{Attributes,Groups}/  # EF mappings
```
